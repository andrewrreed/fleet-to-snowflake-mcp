What we hit in testing

Asked for 1995 revenue, Analyst filtered on L_SHIPDATE while the Agent used O_ORDERDATE. Europe came back as $6.718B vs $6.702B.

One rule fixed both

"Year questions use order date" added to the semantic view. Every agent and tool that reads it now agrees. Define it once, inherit it everywhere.

authentication

Each person signs in to Snowflake once

press → to walk through sign-in

Four stages: connect, sign in, exchange, then every question after that.

1 · connect

You add the Snowflake MCP server in Fleet. Fleet hands off to the LangSmith OAuth provider, which sends your browser to Snowflake's sign-in page. PKCE ties this request to the code that comes back, so it can't be intercepted and reused.

2 · sign in

You sign in on Snowflake's own page, with your Snowflake credentials or SSO, and approve access. LangSmith and Fleet never see your password.

3 · exchange

Snowflake sends a one-time code to LangSmith's callback URL. LangSmith trades it, plus the client secret, for an access token and a refresh token issued to you, under an allowed role.

4 · every question

Each Fleet tool call carries your token. Snowflake runs the session as your role, so your grants decide what every query can reach. The refresh token renews access without signing in again (up to a day in this setup).

access control

How Snowflake roles are respected

gate 1 · oauth integration

Which roles may sign in

ALLOWED_ROLES_LIST names the roles Fleet sessions may use. ACCOUNTADMIN and other admin roles are blocked by default.

→
gate 2 · session role

One role per session

The session runs as the user's role, from the token's scope or their default. OAUTH_USE_SECONDARY_ROLES = NONE stops other roles leaking in.

→
gate 3 · object grants

Each tool checks grants

USAGE on the agent, SELECT on the semantic view and tables. run_sql is read-only.

→

Split servers by access

A server is an access boundary: e.g. ANALYTICS_MCP for everyone, FINANCE_MCP for finance roles.

No "view of views"

The router combines domains. Add a broader view only where cross-domain questions are common.

Shared dimensions

Define region, customer and date the same way in every view so answers line up.

MCP server

Choose the tools. Split servers by who may use them.

Roles and grants

Server, agent, views and tables. Default role and warehouse per user.

OAuth

Snowflake integration ⇄ LangSmith provider ⇄ Fleet connection.

Start with pattern B when Fleet owns the reasoning, mixes in other tools, and you want every step traced.
Use pattern A where a governed Cortex Agent is the product, or Snowflake should orchestrate Analyst, Search and charts.

In production, put run_sql on its own server and role. Never grant MCP roles to PUBLIC.
