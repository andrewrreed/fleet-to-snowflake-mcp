the ask

How do Fleet agents get answers
from Snowflake data?

Governed metrics

"Revenue" means the same thing in every answer, no matter which agent asks.

Per-user access

Each person queries as themselves, under the Snowflake roles they already have.

Traceable

See what was asked, which SQL ran and what came back, in LangSmith.

The catch: Snowflake has no account-wide MCP endpoint. You create an MCP server object, choose its tools, and grant access to the server and to every object behind each tool.

the building blocks

Five Snowflake pieces

MCP serverA schema object that exposes up to 50 tools. Fleet connects to its URL.CREATE MCP SERVER
Cortex AgentPlans, writes and runs SQL, can search documents and draw charts. Returns an answer.CORTEX_AGENT_RUN
Cortex AnalystTurns a question into SQL over a semantic view. Returns SQL only, not data.CORTEX_ANALYST_MESSAGE
Read-only SQLRuns a SELECT as the signed-in user's role and returns rows.SYSTEM_EXECUTE_SQL
Semantic viewThe semantic layer: business definitions over tables, covering joins, dimensions, metrics, synonyms and SQL rules.CREATE SEMANTIC VIEW

Access to the server lets a client list tools. Each tool still needs its own grant: USAGE on the agent, SELECT on the semantic view, SELECT on tables for SQL.

beyond one demo

General-purpose chat across many domains

Each business domain gets a semantic view, and each Analyst tool covers exactly one view (we tested this). A router picks the right view for each question. The only design choice is where that router lives.

One view per domain

Define shared dimensions (region, customer, date) the same way in every view so answers line up.

No "view of views"

The router combines results across domains. Build a broader view only where cross-domain questions are common.

Servers are access boundaries

Group tools by who may use them. Each user's OAuth role decides which tools succeed.

authentication

OAuth, registered by hand

Fleet's Auto mode needs dynamic client registration, which Snowflake doesn't support. Manual mode registers the same client on both sides.

what we learned

Lessons and production notes

Fix it once in the semantic view

For "revenue in 1995", Analyst first filtered on ship date and the agent on order date, giving different totals. One SQL rule in the semantic view fixed it for both.

Mind pattern A's payload

The agent tool returns its whole run, about 31 KB. Instruct the Fleet agent to use only the final answer.

Isolate raw SQL in production

Put run_sql on its own server with its own least-privileged role, so it can't bypass an agent's guardrails.

Keep roles tight

Never grant MCP roles to PUBLIC. Write precise tool descriptions. MCP servers aren't replicated by failover groups, so script them.

Start with B when Fleet owns the reasoning and you want every step traced. Use A where a governed Cortex Agent is the product.
